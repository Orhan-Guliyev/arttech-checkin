# Система учета рабочего времени

Веб-приложение для фиксации прихода и ухода сотрудников с записью времени, геолокации и автоматическим отображением смен на интерактивной карте. Проект выполнен в рамках тестового задания.

---

## Основной функционал

### Для сотрудников (`worker1@company.com`, `worker2@company.com`, и т.д.):

* **Чек-ин / Чек-аут:** Фиксация времени начала и окончания смены.


* **Геолокация:** Автоматическое определение координат (широта/долгота) через Geolocation API браузера.


* **Статусы:** Отображение текущего состояния («На работе» / «Не на работе»).


* **Интерактивная карта:** Визуализация точек прихода (зеленый маркер) и ухода (красный маркер) Leaflet. При совпадении координат маркеры автоматически смещаются для наглядности.


* **Подсчет времени:** Автоматический расчет длительности смены, а также агрегированная статистика за неделю, месяц и всё время.


* **Экспорт:** Выгрузка личной истории смен в форматах **CSV** и **Excel (.xlsx)**.



### Для руководителя (`boss@company.com`):

* **Просмотр всех смен:** Доступ к логам всех сотрудников предприятия.


* **Фильтрация:** Фильтр смен по конкретному сотруднику или просмотр всей компании.


* **Общая карта и статистика:** Отображение маркерной карты смен выбранного сотрудника и суммарной наработки.


* **Экспорт отчетов:** Скачивание общего отчета в CSV и Excel.

## Технологический стек

* **Frontend:** HTML5, CSS3, JavaScript (ES6+).


* **Backend & Database:** [Supabase](https://supabase.com/) (PostgreSQL + Auth + Row Level Security).


* **Карты:** [Leaflet.js](https://leafletjs.com/) + OpenStreetMap.


* **Экспорт данных:** [SheetJS (xlsx)](https://github.com/SheetJS/sheetjs).

## Структура базы данных (Supabase SQL)

Для работы приложения в базе данных Supabase создана таблица `work_logs` и настроена политика безопасности **Row Level Security (RLS)**:

```sql
CREATE TABLE work_logs (
    id UUID DEFAULT uuid_generate_v4() PRIMARY KEY,
    user_id UUID REFERENCES auth.users(id) NOT NULL,
    user_email TEXT NOT NULL,
    check_in_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    check_in_lat DOUBLE PRECISION,
    check_in_lng DOUBLE PRECISION,
    check_out_time TIMESTAMP WITH TIME ZONE,
    check_out_lat DOUBLE PRECISION,
    check_out_lng DOUBLE PRECISION,
    duration_minutes INTEGER
);

ALTER TABLE work_logs ENABLE ROW LEVEL SECURITY;

-- Политики и что они делают
-- боссу видно все а сотрудники видят все только свое
CREATE POLICY "View Policy" ON work_logs
FOR SELECT USING (
    auth.email() = 'boss@company.com' OR auth.uid() = user_id
);

-- сотрудники могут создавать свои записи
CREATE POLICY "Insert Policy" ON work_logs
FOR INSERT WITH CHECK (
    auth.uid() = user_id
);

-- сотрудники могут обновлять только свои данные 
CREATE POLICY "Update Policy" ON work_logs
FOR UPDATE USING (
    auth.uid() = user_id
);

```

## Инструкция по локальному запуску

Проект выполнен без использования тяжелых сборщиков (Vite/Webpack), поэтому не требует установки `npm` зависимостей.

### Запуск через Live Server (Рекомендуется)

1. Клонируйте или скачайте репозиторий с исходным кодом.
2. Откройте папку проекта в **VS Code**.
3. Установите расширение **Live Server** (если не установлено).
4. Нажмите правой кнопкой мыши по файлу `index.html` и выберите **"Open with Live Server"**.

> **⚠️ Важное примечание по геолокации:** Браузеры блокируют определение геолокации при простом открытии файла. Обязательно запускайте проект через локальный веб-сервер и разрешите доступ к геопозиции во всплывающем окне браузера.

## Fault Tolerance

1. **Отказ в геолокации:** Если пользователь запретил доступ к геопозиции или произошел сбой спутников, приложение не падает — запись смены сохраняется с пустыми координатами (`null`), а пользователь получает уведомление в интерфейсе.


2. **Адаптивность:** Таблицы оснащены горизонтальной прокруткой, а блоки статистики перестраиваются для корректного отображения на мобильных устройствах.
